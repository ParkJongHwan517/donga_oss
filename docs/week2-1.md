## Week 2-1 데이터 스키마 설계

### 1. 목표

1주차에 정의한 FIT의 핵심 기능을 구현하기 위해 데이터 구조를 설계한다.

이번 주차에서는 참조 의류와 상품의 데이터를 구분하고, 각 데이터에 필요한 필드와 테이블 관계를 정리한다.

### 2. 참조 의류 데이터

사용자가 가지고 있는 의류의 정보를 저장한다.

| 필드      | 설명              |
| --------- | ----------------- |
| id        | 참조 의류 고유 ID |
| user_id   | 사용자 ID         |
| name      | 참조 의류 이름    |
| waist_cm  | 허리 실측값       |
| thigh_cm  | 허벅지 실측값     |
| rise_cm   | 밑위 실측값       |
| hem_cm    | 밑단 실측값       |
| length_cm | 총장 실측값       |
| fit_tag   | 착용감 정보       |

- 실측값은 cm 단위로 저장한다.
- 초기 MVP는 남성 하의를 기준으로 한다.
- 한 사용자가 여러 참조 의류를 등록할 수 있도록 설계한다.

### 3. 상품 실측 데이터

하나의 상품에 여러 사이즈가 존재할 수 있으므로 상품 기본 정보와 사이즈별 실측값을 분리한다.

#### 3-1. 상품 기본 정보

| 필드              | 설명           |
| ----------------- | -------------- |
| id                | 상품 고유 ID   |
| name              | 상품명         |
| source            | 데이터 출처    |
| source_product_id | 원본 상품 ID   |
| product_url       | 원본 상품 링크 |

#### 3-2. 사이즈별 실측값

| 필드       | 설명                  |
| ---------- | --------------------- |
| id         | 사이즈 데이터 고유 ID |
| product_id | 상품 ID               |
| size_label | 사이즈명 (S, M, L 등) |
| waist_cm   | 허리 실측값           |
| thigh_cm   | 허벅지 실측값         |
| rise_cm    | 밑위 실측값           |
| hem_cm     | 밑단 실측값           |
| length_cm  | 총장 실측값           |

### 4. 테이블 관계

- 사용자 1명은 여러 참조 의류를 등록할 수 있다.
- 상품 1개는 여러 사이즈 정보를 가질 수 있다.
- 참조 의류와 상품 사이즈는 실측값을 기준으로 비교한다.

### 5. 추가 검토사항

#### 5-1. 실측값 누락

1주차 조사에서 밑위 실측값이 제공되지 않는 상품이 있었다는 것을 발견했다.

따라서 일부 실측값이 없는 경우에도 상품 데이터를 저장할 수 있도록 검토한다.

#### 5-2. 측정 기준 차이

쇼핑몰마다 허리 단면, 허리 둘레 등 측정 기준이 다를 수 있다.

비교하기 전에 측정 기준과 단위를 통일할 필용가 있다.

#### 5-3. 데이터 정확도

1주차 테스트에서 일부 상품의 숫자 인식 오류가 발생하였다.

테스트 결과를 그대로 사용하지 않고 원본 사이즈표와 비교하며 검증하는 방법을 고려한다.

### 6. 초기 구성

초기 MVP에서는 다음 테이블을 기준으로 설계한다.

- reference_clothes: 사용자의 참조 의류
- products: 비교 대상 상품 정보
- product_sizes: 상품 사이즈별 실측값

#### 6-1. 사용자 데이터 접근 제어

사용자별 참조 의류는 다른 사용자에게 노출되지 않아야 한다

본인이 등록한 참조 의류만 조회 및 수정할 수 있도록 설계한다.
