## Week 2-1 데이터 스키마 설계

### 1. 목표

1주차에 정의한 FIT의 핵심 기능을 구현하기 위해 데이터 구조를 설계한다.

이번 주차에서는 참조 의류와 상품의 데이터를 구분하고, 각 데이터에 필요한 필드와 테이블 관계를 정리한다.

### 2. 참조 의류 데이터

사용자가 가지고 있는 의류의 정보를 저장한다.

| 필드      | 설명              |
| --------- | ----------------- |
| id        | 참조 의류 고유 ID |
| user_id   | 사용자 ID         |
| name      | 참조 의류 이름    |
| waist_cm  | 허리 실측값       |
| thigh_cm  | 허벅지 실측값     |
| rise_cm   | 밑위 실측값       |
| hem_cm    | 밑단 실측값       |
| length_cm | 총장 실측값       |
| fit_tag   | 착용감 정보       |

- 실측값은 cm 단위로 저장한다.
- 초기 MVP는 남성 하의를 기준으로 한다.
- 한 사용자가 여러 참조 의류를 등록할 수 있도록 설계한다.

### 3. 상품 실측 데이터

하나의 상품에 여러 사이즈가 존재할 수 있으므로 상품 기본 정보와 사이즈별 실측값을 분리한다.

#### 3-1. 상품 기본 정보

| 필드              | 설명           |
| ----------------- | -------------- |
| id                | 상품 고유 ID   |
| name              | 상품명         |
| source            | 데이터 출처    |
| source_product_id | 원본 상품 ID   |
| product_url       | 원본 상품 링크 |

#### 3-2. 사이즈별 실측값

| 필드       | 설명                  |
| ---------- | --------------------- |
| id         | 사이즈 데이터 고유 ID |
| product_id | 상품 ID               |
| size_label | 사이즈명 (S, M, L 등) |
| waist_cm   | 허리 실측값           |
| thigh_cm   | 허벅지 실측값         |
| rise_cm    | 밑위 실측값           |
| hem_cm     | 밑단 실측값           |
| length_cm  | 총장 실측값           |
